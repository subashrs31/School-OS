# Sub-phase 2.1 — Prisma foundation: profile, RBAC & tenancy schema

**Status:** Spec — not started · **Depends on:** 2.0 tooling, ADR-001/002/003/005 approved
**Task type:** Architecture / new schema (no behaviour change for existing endpoints yet)
**Revised 2026-09-30:** identity (credentials, 2FA, lockout) moved to the license server (ADR-005). `users` here is a
profile keyed by `identity_subject`.

## 1. Requirement
Create the PostgreSQL schema, through Prisma, for the ten profile, RBAC and tenancy tables in `SOS_DATABASE_DESIGN.md`
§3–§4 (with §4.1 `users` reduced to its profile columns), enforce the design's isolation and uniqueness rules in the
database, and seed roles and permissions (§11). Existing Sequelize code keeps running against MySQL until Phase 4/5
switches each module.

## 2. Scope
**In:** `users`, `roles`, `permissions`, `role_has_permissions`, `user_has_roles`, `user_has_permissions`,
`organizations`, `branches`, `organization_social_links`, `audit_logs`; seed script; constraint SQL; integration tests.

**Out:** invitations and support sessions (2.2), people/academics/exams (2.3–2.5), any API or FE change, data
migration from MySQL (2.7), removing Sequelize (2.8).

## 4. Schema decisions (design doc wins; open items flagged ⏸)
| Topic | Decision |
|---|---|
| Naming | `snake_case` tables/columns via `@@map`/`@map`; camelCase in TS |
| Keys | `id` BigInt/Int autoincrement (Int unless volumes justify BigInt — Int chosen); `public_id` UUID `@default(uuid())` on users and organizations |
| `users` (profile) | `id`, `public_id`, `identity_subject` TEXT(64) **unique NN** (license-server `sub`), `account_plane`, `display_name`, `email`/`mobile` (display copies, not unique here — uniqueness is the license server's job), `preferred_language`, `status` (ACTIVE, DISABLED), `access_version`, `last_seen_at`, AUDIT, VERSION. **Not here:** password_hash, two_factor_*, failed_attempts, locked_until, password_changed_at, must_change_password (design §4.1 columns moved to the license server) |
| Enums | Design values (UPPERCASE) — except `role_type` and `scope_type`, which keep existing lowercase values (design §4.2, §4.5) |
| AUDIT / VERSION blocks | `created_at`, `created_by`, `updated_at`, `updated_by`, `row_version` as specified per table |
| Case-insensitive uniques | `organizations.slug` unique on `lower(...)` (raw SQL) |
| Pair uniques | `branches @@unique([organizationId, id])` and `@@unique([organizationId, code])` |
| Scope columns | `user_has_roles`/`user_has_permissions`: `scope_type`, `scope_id`, `organization_id`, `branch_id` + CHECK constraints (design §4.5 rules) |
| Branch belongs to org | `user_has_roles (organization_id, branch_id)` → FK to `branches (organization_id, id)` |
| Partial uniques (raw SQL) | one default branch per org; one active identical assignment per `(user, role, scope)` where `revoked_at IS NULL` |
| `organizations` ↔ license | `status_source` defaults to `MANUAL`; becomes `SUBSCRIPTION` once the license webhook (4.6) is live; `public_id` is the tenant id shared with the license server |
| Self-service sign-up (ADR-007) | add `signup_source CHOICE(PLATFORM, SELF_SERVICE)` and make `onboarded_by` nullable — ⏸ pending ADR-007 approval and the owner's note in the design doc |
| Circular `created_by` | plain nullable INT references added after tables exist (design §10) |
| `audit_logs` | append-only; index `(organization_id, occurred_at)`; `change_summary` jsonb; no update/delete in app code |
| ⏸ `roles.slug` → `key` | Design uses `key`; seeded slugs (`super-admin`) become keys (`super_admin`). FE and seed references updated in Phase 4.4 |
| ⏸ Permission keys | Keep `resource.action` (dot); add `module`, `is_sensitive`, `is_platform_only`; drop the unused `role-permission.*` set |

## 5. Acceptance criteria
1. **Given** an empty test database, **when** the migration is applied, **then** all ten tables, enums, indexes, FKs,
   CHECKs and partial unique indexes exist (verified by an integration test querying `pg_indexes` / `pg_constraint`).
2. **Given** a branch of school A, **when** inserting a `user_has_roles` row with `organization_id` = school B and that
   branch, **then** Postgres rejects it (FK violation).
3. **Given** `scope_type = 'global'`, **when** `organization_id` is set, **then** the CHECK rejects it; likewise for
   the organization and branch rules in design §4.5.
4. **Given** a role with `role_type = 'primary'`, **when** assigned with `scope_type = 'organization'`, **then** it is
   rejected (CHECK via role-type compatibility enforced in the service layer + test; DB cannot reference another
   table in CHECK — see note).
5. **Given** a school with a default branch, **when** a second branch is inserted with `is_default = true`, **then**
   the partial unique index rejects it.
6. **Given** two schools, **when** both create branch code `MAIN`, **then** both succeed; the same school twice → rejected.
7. **Given** a profile with `identity_subject = 'ls-123'` exists, **when** another profile with the same subject is
   inserted, **then** rejected; the `users` table has **no** password, 2FA or lockout columns (asserted via
   `information_schema.columns`).
8. **Given** the seed runs twice, **then** it is idempotent (no duplicates) and creates the roles/permissions of design §11
   and one super-admin profile linked to `SEED_SUPER_ADMIN_SUBJECT` with a global `super_admin` assignment (seed fails
   with a clear message if the variable is missing).
9. `npx prisma validate` and `tsc --noEmit` pass; existing endpoints unaffected (no Sequelize code changed).

Note on AC4: role-type/scope compatibility spans two tables, so it is enforced in the assignment service (Phase 4.4)
with a unit test, and optionally a trigger; the trigger is **not** added in 2.1 unless approved.

## 10. Database changes
New PostgreSQL database only. **No change to MySQL.** Commands the owner runs (assistant does not):
```bash
docker compose up -d postgres
npx prisma migrate dev --create-only --name init_identity_tenancy   # generate SQL for review
# review + append constraint SQL, then:
npx prisma migrate dev                                            # apply to dev DB
DATABASE_URL=$TEST_DATABASE_URL npx prisma migrate reset --force   # test DB only
npm run db:seed
```

## 12. Risks & rollback
| Risk | Mitigation |
|---|---|
| Prisma regenerates a migration and drops hand-written constraints | AC1 test asserts every constraint by name |
| `lower()` unique on slug conflicts with Prisma `@unique` | declare uniqueness only in SQL for that column |
| Profile exists before the license-server identity (seed order) | seed only needs the subject string; LS-1 creates the identity with the same `sub` |
| Rollback | drop the Postgres database; MySQL path is untouched |
